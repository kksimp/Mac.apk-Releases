# Mac.apk flags reference

Every environment variable and command-line flag the Mac.apk runtime, launcher, build
scripts and developer harnesses read, with its default, its accepted values and what it
does. This is the developer's reference; the handful of flags a user is likely to want are
summarised in the README's "Advanced: flags and settings" section and repeated in the first
table below.

The `Source` column cites the file and line in the Mac.apk source tree that reads each
flag, as of the date in the heading; the audience column classifies each row as `user`,
`dev`, `diag` (diagnostic output), `bisect` (a gate that restores an older behaviour for an
A/B), `experiment` or `harness` (read only by a script under `debug/`, never by the shipped
runtime). Flags marked `bisect` or `experiment` are not supported configurations; they exist
so a regression can be attributed, and a future release may remove them without notice.
Diagnostic switches that exist only for the maintainers' investigation of one specific app
are left out of this copy.

# TL;DR: every MACAPK_* environment variable, every macapk-runtime/macapk-translator CLI flag, and every user-facing build/harness script switch in the Mac.apk tree, grouped by subsystem, with default/values/effect/source/audience for each.

This is the full flag inventory for Mac.apk, built by grepping every `getenv`/`System.getenv`/`ProcessInfo...environment[...]`/shell-`$VAR` read across `runtime/`, `launcher/`, `scripts/`, and `debug/`, cross-checked against the actual reading code (never invented from the name alone). Methodology, counts, and known gaps are in "OPEN QUESTIONS / NEXT" at the end.

**Scope note.** `MACAPK_*`-prefixed identifiers that are NOT flags -- C++ `#define`/enum constants (`MACAPK_EPOLLIN`, `MACAPK_CAM_FACING_BACK`, ...), header include-guards (`MACAPK_ARM32RC_REGMAP_H`), internal Java field/constant names that merely follow the project's naming convention (`MACAPK_BUILD_DATE`, `MACAPK_HOST_PACKAGE`, `MACAPK_FW_STYLE_BY_ID`, ...), and CMake build variables (`MACAPK_VERSION_STR`, `MACAPK_RUNTIME_SOURCES`) -- are excluded entirely; they are not settable by a user or script. Roughly 190 of the ~1,267 raw `MACAPK_[A-Z0-9_]+` name-matches in the tree fall in this excluded category. A handful of additional names that read like flags in a comment but resolve to zero live `getenv`-style call anywhere are listed in the STALE table near the end instead of silently dropped, since a future session searching for them should find out why they don't work rather than conclude the grep missed something.

## How to set a flag

- **Direct binary run (dev):** environment variables go before the command: `MACAPK_LOG_LEVEL=7 runtime/build/bin/macapk-runtime --apk path/to/app.apk`. CLI flags (`--orientation`, `--android-root`, ...) go on the command line as shown in the CLI tables below.
- **An installed app:** `MACAPK_X=1 /Applications/<App>.app/Contents/MacOS/<AppStub>` from a Terminal -- the per-app stub `execv`s the staged shared runtime and inherits whatever environment it was started with, exactly like any other macOS executable. `open` does NOT forward a shell's environment to the launched app (macOS launch services strips it); use `open --env MACAPK_X=1 -a /Applications/<App>.app` (per-key) or launch the binary inside `Contents/MacOS/` directly if you need this from a script.
- **The launcher GUI does three separate things**, in increasing order of specificity (later wins):
  1. Its own Settings panel translates screen-size / orientation / verbose-logging pickers into the matching `--width/--height`, `--orientation`, and `--verbose` CLI flags, and a few Dev-menu toggles (revealed by 5-tapping the launcher's title) into specific env vars -- see "Launcher settings surface" below for the exact mapping.
  2. **Settings > Default environment** is a freeform key=value editor applied to *every* launch -- this is the general escape hatch for typing any `MACAPK_*` var (or anything else) without touching a Terminal at all.
  3. An individual app's **Get Info sheet** holds a *per-app* freeform key=value editor that is applied on top of (and overrides) the global Default environment for that one app only.
  (`launcher/MacApkLauncherApp.swift`, around the `proc.environment = env` assembly: global `model.defaultEnv` is applied, then the per-app `app.env` on top, so a per-app override always wins over the global default.)
- **A script that shells out to the runtime** (any of `scripts/*.sh`, `debug/*.sh`) reads its own knobs the same way any shell script does: `MACAPK_SWEEP_MODE=x scripts/sweep.sh`, etc. See the Harnesses table for the full list.

## The 12 flags a user actually needs

*(Everything else in this document exists for developers/RE work; these are the ones worth knowing about for normal use. Full citations are in the subsystem tables below -- this is a copy-paste-friendly summary for a README.)*

| Flag | What it does |
|---|---|
| `--android-root <dir>` (CLI) / `MACAPK_ANDROID_ROOT` | Where the runtime creates the Android filesystem mirror (`data/data/<pkg>/...`) for the app being launched -- saves live here. Default (bare dev invocation only; an installed app's stub always passes its own bundle path) is `~/Library/Caches/Mac.apk/scratch/android`; also settable from the launcher's Settings panel folder picker. |
| `--orientation auto\|portrait\|landscape` (CLI) | Window orientation. `auto` reads the launchable activity's `android:screenOrientation` from the manifest and falls back to portrait. Exposed as a Picker in the launcher. |
| `--width N --height N` (CLI) | Explicit window pixel size, overriding the orientation default. Exposed as a size-preset Picker in the launcher (an "Auto" preset omits these and uses the biggest canvas the display supports). |
| `--fullscreen` / `MACAPK_FULLSCREEN=1` | Launches the app in a fullscreen window instead of a titled one. |
| `--hide-dock-icon` / `MACAPK_HIDE_DOCK_ICON=1` | Hides the runtime's own Dock icon/tile for this launch. |
| `MACAPK_FOLLOW_SYSTEM_APPEARANCE=0` | Forces light mode regardless of the Mac's current appearance. Unset (default) follows macOS's light/dark setting. |
| `--force-abi armeabi-v7a` (CLI) / `MACAPK_FORCE_ABI` | Forces the ARM32 lifter/recompiler path even when the APK ships an `arm64-v8a` library it would otherwise prefer. This is the launcher's "Force ARM32" Dev-menu toggle. |
| `MACAPK_LOG_LEVEL=<0-7>` | Runtime log verbosity floor (mirrors AOSP's own per-tag priority filter; unset defaults to INFO, AOSP's own default floor). Level 7 is needed to unlock the lowest-level `NativeLog.print` diagnostics. |
| `--dev-trace` (CLI) / `MACAPK_DEV_TRACE=1` | Turns on the broad diagnostic-tracing master switch (JNI, bionic-shim trace points, ...) in one step. Expect roughly 1 fps on a big game while it's on. This is the launcher's "Verbose trace (very slow)" Dev-menu toggle. |
| `MACAPK_ALLOW_UNSAFE_X18=1` | Diagnosis-only escape hatch that lets an arm64 guest load even when the host's x18-preservation capability probe fails. Never a fix for a real failure; see `CLAUDE.md`'s "Build" section. |
| `MACAPK_INSTALL_NOUI=1` | Skips the install confirmation dialog -- useful for a scripted/unattended install (`open --env MACAPK_INSTALL_NOUI=1 -a /Applications/Mac.apk.app <apk>`). |
| `MACAPK_EXTRACT_ASSETS=1` | Restores the pre-v1.0.1585 behaviour of extracting an app's assets onto disk instead of reading them from the installed APK in place. A bisect gate; only worth trying if an app that used to work stops finding its own assets. |

## CLI flags: `runtime/build/bin/macapk-runtime`

Parsed by `ParseArgs()` in `runtime/src/main.cpp:123-249`. Usage banner at `main.cpp:93-121`.

| Flag | Required/optional | Effect |
|---|---|---|
| `--apk <path>` | Required unless `--peek-manifest` or `--gms` is given | The APK to launch. Made absolute (not symlink-resolved) before use, because `ApplicationInfo.sourceDir`/`getPackageCodePath()` etc. must answer with an absolute path the way a device does (`main.cpp:133-161`). Also exported as `MACAPK_APK_PATH` so `PresentedSdk` can read `targetSdkVersion` from the binary manifest before the framework's `Build.<clinit>` runs -- apktool strips `<uses-sdk>` from every decoded manifest, so the binary manifest is the only reliable source at that point. |
| `--width N` / `--height N` | Optional | Explicit window pixel size; overrides whatever the resolved orientation would have picked (`main.cpp:163-164`). |
| `--orientation auto\|portrait\|landscape` | Optional, default `auto` | `auto` reads `android:screenOrientation` off the launchable activity and falls back to portrait; `portrait`/`landscape` force it unconditionally (`main.cpp:165-178`). `--portrait`/`--landscape` are bare aliases for the same thing (`main.cpp:181-182`). |
| `--android-root <dir>` | Optional | User-visible directory for the Android filesystem mirror. Sets `MACAPK_ANDROID_ROOT` so every independent root-resolver downstream (the unpacker's cache fallback, `Boot.java`'s env chain, the GLES3.1 verdict cache) agrees (`main.cpp:192-201`). Falls back to the `MACAPK_ANDROID_ROOT` env var if the flag is absent, then to a compiled-in default expanded once `$HOME` is known (`main.cpp:242-247`). |
| `--verbose` | Optional | Sets the CLI-level verbose flag (`main.cpp:203`). |
| `--extract-only` | Optional | Non-launching mode: runs `apk_unpacker` + the android-root asset extract to backfill manifest/icon/`meta.json` for the launcher's Installed-Apps panel, then exits 0 -- no JVM, no Cocoa window, no native libs loaded (`main.cpp:63-70, 204`). |
| `--peek-manifest <apk>` | Optional | Prints one JSON line (`package`, `versionCode`, `versionName`, `label`) read from the **binary** manifest, then exits. No extraction, no JVM, no window -- used so the install confirm dialog can show identity before paying for any of that (`main.cpp:86-90, 214`). |
| `--gms <subcommand> [args...]` | Optional | Drives the GMS/Play-Services layer (accounts, sign-in, tokens, licensing) with no APK loaded. Everything after `--gms` is passed through verbatim as the subcommand's own args (`main.cpp:71-77, 205-213`). This is the only path that can put the Google sign-in page on screen for the launcher's Accounts panel, and the only way an installed app (no launcher process to delegate to) gets one. Subcommands are handled by `com.macapk.gms.GmsCli` on the Java side (not further enumerated here; out of scope for a flag reference). |
| `--fullscreen` | Optional | Sets `MACAPK_FULLSCREEN=1` for this process (`main.cpp:188`) -- see the env var's own row in "Launch & window" below. |
| `--hide-dock-icon` | Optional | Sets `MACAPK_HIDE_DOCK_ICON=1` (`main.cpp:189-191`). |
| `--dev-trace` / `--verbose-trace` | Optional | Sets `MACAPK_DEV_TRACE=1`, `MACAPK_TRACE_BL=1`, `MACAPK_TRACE_JNI_HANDLES=1` in one step -- the CLI/headless equivalent of the launcher's "Verbose Trace" Dev-menu toggle. Warns that it costs roughly 1 fps on HCR-class games (`main.cpp:215-230`). |
| `--force-abi <abi>` | Optional | Sets `MACAPK_FORCE_ABI=<abi>` -- the CLI equivalent of the launcher's "Force ARM32" toggle, so a headless run doesn't need a separate shell-env layer (`main.cpp:231-237`). |
| `-h` / `--help` | -- | Prints the usage banner and exits 0 (`main.cpp:238`). |

Any unrecognized flag, or no `--apk`/`--peek-manifest`/`--gms` at all, prints usage and exits 2 (`main.cpp:239-241`).

## CLI flags: `runtime/build/bin/macapk-translator`

Parsed in `runtime/translator/src/main.cpp:6946-6983`. Usage banner at `main.cpp:65-69`. Invoked as a subprocess by `runtime/src/apk_unpacker.cpp` for every `.so` the DEX-conversion/unpack step finds; also runnable standalone for RE work.

| Flag | Required/optional | Effect |
|---|---|---|
| `--in <input.so>` | Required | Input ELF (ARM32 or arm64). The class byte (`e_ident[4]`) picks the pipeline: `ELFCLASS32` goes through `elf_reader` + `arm32_lifter`/`arm32rc` (lift/recompile to arm64 dylib); `ELFCLASS64` goes through `elf64_reader` + `arm64_pack` (embed the original bytes verbatim in a small Mach-O wrapper, since the host CPU already IS arm64) (`main.cpp:1-19, 6985-7009`). |
| `--out <output.dylib>` | Required | Output Mach-O dylib path. |
| `--shim-dir <dir>` | Optional | Directory the emitted dylib links its Bionic shims against. Defaults to the directory containing the `macapk-translator` binary itself if omitted (`main.cpp:6974-6982`). |
| `--keep-ir` | Optional (flag, no value) | Materialises the lifter's `.ll` IR text as a debugging artifact. Historical note: nothing compiles this IR any more (arm32rc emits Mach-O directly since the v1.0.802 cutover) -- it exists purely so a human or `debug/` script can read it (`main.cpp:1147-1156, 1254-1278`; see also CLAUDE.md's "LLVM nobuiltin" historical section). |
| `--emit-discovery <path>\|auto` | Optional | Where to write the ARM32 discovery sidecar (`<output>.disc.tsv`), or omit for none. The literal values `1`/`auto` both mean `<output-dylib>.disc.tsv`, the name `debug/arm32_sidecar.py`'s `sidecar_path_for` looks for. `MACAPK_DISCOVERY_SIDECAR` is the env-var equivalent for callers (like `apk_unpacker.cpp`) that build the translator's argv themselves and don't add a new flag per call (`main.cpp:74-83`). |
| `--load-bias <hex-or-decimal>` | Optional, default 0 | Per-image guest-arena byte offset (parsed with `strtoul(..., 0)`, so `0x...` or decimal both work). 0 means the main/single-`.so` image (bit-identical output); the runtime assigns a non-zero bias to a 2nd+ `.so` so multiple libraries don't collide in the shared guest arena (`main.cpp:6953-6956, 6968`). |
| `--strict` | Optional | Sets the internal `strict` flag (consumed further down the pipeline; not further documented at the parse site). |
| `--verbose` / `-v` | Optional | Prints extra per-file diagnostics (symbol/segment counts, load-bias value) (`main.cpp:7000-7008`). |
| `-h` / `--help` | -- | Prints usage and exits 0. |

`--in`/`--out` are the only two truly required; anything else missing/unrecognized prints usage and exits 2.

## Launcher settings surface (`launcher/MacApkLauncherApp.swift`)

The GUI translates a small set of pickers/toggles into the CLI flags and env vars above, then layers freeform user text on top:

| Setting | Maps to |
|---|---|
| Canvas-size preset Picker | `--width`/`--height` (omitted for the "Auto" preset, which lets the runtime pick the biggest size the display supports for the resolved orientation) |
| Orientation Picker (Auto/Portrait/Landscape) | `--orientation <value>` |
| "Show live log panel (verbose)" toggle | `--verbose` |
| "Write log to folder" toggle | Launcher-local file logging; not an env var passed to the runtime. |
| Android-root / app-storage folder picker ("where app files are stored") | `MACAPK_APP_CACHE_DIR` (the runtime's `apk_unpacker` treats this as authoritative when set; kept deliberately outside `runtime/build/var/apps/`, which `rebuild_and_run.sh` wipes wholesale) |
| App icon / label (derived automatically per installed app, not user-typed) | `MACAPK_APP_ICON`, `MACAPK_APP_LABEL`, `MACAPK_DEFAULT_ICON` (fallback icon bundled next to the runtime) |
| Dev menu -> "Force ARM32" toggle (menu revealed by 5-tapping the launcher's title) | `MACAPK_FORCE_ABI=armeabi-v7a` |
| Dev menu -> "Verbose trace (very slow)" toggle | `MACAPK_DEV_TRACE=1`, `MACAPK_TRACE_BL=1`, `MACAPK_TRACE_JNI_HANDLES=1` |
| "Verbose logging (all classloads)" toggle | When **off** (the default, for a fast/quiet UI run): sets `MACAPK_LOG_LEVEL=4` + `MACAPK_QUIET_CLASSLOAD=1`. When **on**: sets neither, so the run stays at AOSP's own INFO-level default floor with the classloader pair unsuppressed. A direct CLI run (no launcher involved) sets neither and is verbose by default. |
| "Show app versions in Applications" toggle | Cosmetic UI only (adds the version string to the Applications-panel row label); not an env var. |
| **Settings > Default environment** | Freeform key=value list, applied to every launch. |
| Per-app **Get Info** sheet environment | Freeform key=value list for that one app, applied on top of (overriding) the global Default environment. |

Order of application (`MacApkLauncherApp.swift`, the `proc.environment = env` assembly): derived/automatic vars first, then Dev-menu toggles, then the quiet-logging default, then `model.defaultEnv` (global user text), then the selected app's own `app.env` (per-app user text) -- so a per-app override always wins.

Separately, `launcher/AppStubMain.swift` (the tiny per-app stub every installed app actually execs) reads `MACAPK_STUB_LOG` (`=0` disables its own stub-level logging) and `MACAPK_STUB_NO_UI` (`=1` suppresses its error alert panel, so an unattended harness doesn't block on a dialog forever), and `launcher/InstallCore.swift` honours `MACAPK_RUNTIME_ROOT` and `MACAPK_CANONICAL_APP` overrides for where the staged shared runtime and the one canonical installed app live.

## Build / release / staging (dev)

These scripts are what a developer runs to build, promote, and release Mac.apk itself; none of them run at app-launch time.

### `scripts/rebuild_and_run.sh` -- "the owner's one command"

Wipes `runtime/build`, `runtime/translator/build`, and `build/Mac.apk.app`, rebuilds from source, then atomically promotes the result over the one canonical installed app (default `/Applications/Mac.apk.app`), stages the shared runtime every installed app actually executes, prunes stale LaunchServices registrations, and prints the freshness report.

| Flag | Effect |
|---|---|
| `--fresh-caches` | Invalidates only the five named per-app regenerable cache items (never an app's `files/`, `databases/`, `shared_prefs/`, `cache/`, or `services_root/`, and never the app dir itself) -- the explicit escape hatch for forcing old caches cold before the runtime consumes `build-id.txt` freshness natively. |
| `--no-promote` | Builds only; leaves the canonical app untouched, for a deliberate A/B against an older installed build. Also skips staging the shared runtime. |
| `MACAPK_CANONICAL_APP` (env) | Overrides the canonical app path (default `/Applications/Mac.apk.app`). |

### `scripts/build_launcher.sh`

Builds the Swift launcher bundle (`build/Mac.apk.app`) from source.

| Flag | Effect |
|---|---|
| `--promote` | Installs the freshly-built bundle over the ONE canonical app (via `scripts/promote_app.sh`) instead of just leaving it in `build/`. Without this flag the script only WARNS and prints both build ids -- **`scripts/build_launcher.sh` alone, followed by `open build/Mac.apk.app`, never promotes**, a documented historical footgun (CLAUDE.md, "Build", corrected 2026-08-19). |

Also reads (env, not flags): `MACAPK_CANONICAL_APP` (default `/Applications/Mac.apk.app`), `MACAPK_NO_BUNDLE_SYNC` (skip syncing the bundle's runtime copy), `MACAPK_ANGLE_BACKEND` (selects which MoltenVK/ANGLE backend dylib gets bundled, e.g. `vulkan`).

### `scripts/release.sh` -- `[--no-notarize]`

Builds the distributable DMG. Default args are `--dmg --notarize`; `--no-notarize` builds `--dmg` only (skips Apple notarization). Requires `MACAPK_SIGN_IDENTITY` and `MACAPK_NOTARY_ISSUER` to be set (normally sourced from the gitignored `scripts/.release.env`); optionally exports `MACAPK_NOTARY_KEY` / `MACAPK_NOTARY_KEY_ID` (App Store Connect API key path + id, the automation-friendly alternative to a keychain profile) if present.

### `scripts/build_dist.sh` (invoked by `release.sh`, also runnable standalone)

Not one of the explicitly-named scripts but documents the same signing/notarization env vars in one place (`scripts/build_dist.sh:26-38`) -- see the consolidated table below.

### `scripts/build_framework_res.sh`

Builds Android's platform resource table (`framework-res-api<LEVEL>.apk`) from AOSP source with a vendored `aapt2`, as the shippable replacement for apktool's bundled table (wrong API level) and the Google-built emulator-image table (not ours to redistribute).

| Flag | Effect |
|---|---|
| `--api <level>` | Target AOSP API level (e.g. `30`, `34`, `36`). |
| `--tag <aosp-tag>` | AOSP source tag to fetch from (e.g. `android-14.0.0_r1`). |
| `--reference-apk <apk>` | Optional. A reference `framework-res.apk` to diff resource IDs against (verification only, not required to build). |

Also honours `AAPT2=<path>` (not `MACAPK_`-prefixed) to override which `aapt2` binary is used, for a machine where the auto-detected Homebrew/apktool-bundled one isn't right.

### `scripts/stage_framework_res.sh <tools_dir>` (was `scripts/stage_apktool.sh` until v1.0.1590)

Stages the platform resource apk (`tools/framework-res.apk`, the FULL API-36 build from AOSP that `scripts/build_framework_res.sh` produces) next to the runtime, which is what `main.cpp` defaults `MACAPK_FW_RES_APK` to. Until v1.0.1590 the same script also bundled `apktool.jar`; apktool is no longer run by the runtime (Phase 5 step 9: resources, the manifest and the launcher icon are read from the installed apk set in place), so nothing of it ships any more. Its only flag is the positional destination directory, not a `--flag`; its one env var (`MACAPK_ALLOW_TABLE_ONLY_FW`) is in the table below.

## Subsystem reference tables

Every `MACAPK_*` environment variable confirmed to have a real reader somewhere in the tree (1,073 total, see "OPEN QUESTIONS / NEXT" for the exact count and methodology), grouped by the subsystem whose file reads it. Each row is grounded in a specific file:line; effects are paraphrased or lightly quoted from the code's own comment at that site, never invented -- where a site's comment didn't say enough, the row says so instead of guessing.

Diagnostic/trace flags are kept with the subsystem whose file reads them (e.g. `MACAPK_TRACE_SQL` is under Install & storage, `MACAPK_TRACE_TOUCH` is under Launch & window) rather than pooled into one giant trace table. "Logging & tracing" below holds the flags whose reader is a cross-cutting hub file (`bionic_shim.cpp`, `native_methods.cpp`, `arm64_native.cpp`, `cocoa_bridge.mm`) with no more specific subsystem home, plus the two master switches (`MACAPK_LOG_LEVEL`, `MACAPK_DEV_TRACE`).

## Launch & window

*(Diagnostic/trace flags whose primary reader happens to live in a launch/window/activity-lifecycle file are kept here with their subsystem rather than pooled into "Logging & tracing" below -- e.g. `MACAPK_TRACE_TOUCH` sits with touch/activity dispatch, not in the generic trace table.)*
